Web2 Centralized Identity (Module 0) Web2 PKI

1. You create an OpenSSL private/public keypair.

2. You produce a CSR and submit it to a Certificate Authority (DigiCert, Let's Encrypt).

3. The CA signs an X.509 certificate. Clients must trust the CA's root certificate!

Web3 Decentralized Identity (Module 1) Zero CA

1. Generate random scalar on secp256k1 (Private Key).

2. Multiply by curve generator G → Public Key (X, Y).

3. Address = 0x + SHA3-256(PubKey)[12..32].

Math alone guarantees identity & ownership. No third party needed!

Zero-Trust Network Validator Node

When a miner or validator receives a transaction from an unknown peer, it runs these exact mathematical proofs without contacting any central CA.

Verification Pipeline & Proofs Ready to Verify
Proof 1: secp256k1 Curve Point Validation Pending

Reconstructs SPKI DER from 65 uncompressed bytes and ensures public key point satisfies y² = x³ + 7 (mod p).

Proof 2: Identity & Address Derivation Pending

Computes 0x + SHA3-256(coordinates)[12..32] and verifies it matches the claimed tx.data.from. (No Certificate Authority!).

Proof 3: ECDSA Digital Signature Verification Pending

Re-hashes canonical transaction JSON with SHA-256 and executes crypto.verify("SHA256", hash, pubKey, sig).

The Bridge from Module 1 to Module 2 (Blocks & Merkle Trees)

Cryptographic signatures prove who authorized a transaction, but they cannot establish a global chronological order across distributed nodes. To permanently prevent double-spending without a central server, we bundle validated transactions into Blocks linked by hashes (Blockchain) and structured with Merkle Trees — which we will build in Module 2!
